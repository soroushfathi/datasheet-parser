# Runtime and token optimization

The target is a complete, reviewed 17-section / 51-requirement MAX3232 extraction in
30 minutes. This is a measured benchmark target, not a timeout or a guarantee for every
datasheet, model, account or network connection. No roles or requirements are removed.

## New-run configuration

```dotenv
DATASHEET_OPTIMIZATION=budget-v1
DATASHEET_WORKERS=2
DATASHEET_PACKET_TOKEN_BUDGET=6000
DATASHEET_PACKET_IMAGE_TOKEN_BUDGET=6000
DATASHEET_PACKET_MAX_IMAGES=6
DATASHEET_REQUEST_TOKEN_BUDGET=20000
```

For the timing experiment, request three workers explicitly:

```powershell
uv run datasheet run 'C:\Users\Soroush\Downloads\Telegram Desktop\max3232.pdf' `
  --model gpt-6.1-sol --reasoning medium --workers 3 `
  --output .\outputs\MAX3232CD-optimized.json `
  --benchmark-report .\outputs\MAX3232CD-optimized-benchmark.json
```

Select `MAX3232CD / SOIC-16 (D)` in the terminal. Human selection time is excluded from
the benchmark; connection, preparation, catalog lookup/discovery, mapping, model calls,
transport retries, validation and export are included. The report records whether
preparation and catalog were reused. A warm catalog benchmark is not a cold PDF benchmark.
`--target <catalog-target-id>` avoids the selection prompt for reproducible automation.

For the step-by-step workflow:

```powershell
uv run datasheet ingest 'C:\path\to\datasheet.pdf'
uv run datasheet targets <parse-id>
uv run datasheet extract <parse-id> --model gpt-6.1-sol --reasoning medium --workers 3 --prepare-only
uv run datasheet packet <run-id> 2 --output .\work\packets\circuit
uv run datasheet resume <run-id> --output .\outputs\result.json
uv run datasheet trace <run-id>
```

`prepare-only`, `packet` and retrieval evaluation do not perform extraction inference.
`targets` performs discovery if needed. Do not resume the same run in two CLI processes.

## Where time and tokens are saved

| Change | Implementation | Preserved checks |
|---|---|---|
| Source selection | `document_index.ensure_index()` + `Retriever.select()` | Local source headings, target package, relevant engineering topic; metadata is not evidence |
| Atomic source bundles | `build_bounded_packet()` | Whole table, heading, conditions, footnotes and continuations; optional references followed once |
| Image selection | `bounded_packet.py` | Safe table crops; whole pages for circuits, mechanical drawings, unknown visuals and unsafe geometry |
| Compact generation | `section_contract(..., version="compact-v2")` | Raw numeric lexemes, bound roles, units, conditions and citations; public display fields generated by code |
| Compact review | `compact_review()` + `cited_regions()` | All cited sources from both answers, all claim IDs, actual circuit connectivity, independent omission search |
| Bounded concurrency | `Engine.schedule_stages()` | One pool, 1–3 requests total; blind never receives extraction; review waits for both |
| Recovery | Mongo stage records + atomic checkpoints | Completed stages reused; incomplete responses rejected; no automatic expanded source retry |

All model calls still use the selected run model and reasoning. Model routing, reduced
reasoning and removing blind review are not part of this comparison. New runs have
`packet_version=budget-v1`, `contract_version=compact-v2`, `scheduler_version=dag-v1`
and `prompt_version=3`. Older runs retain their previous workflow and contract.

Review also receives the aliases newly available to it but absent from each first reader's
packet. This distinguishes an extraction coverage gap from an incorrect fact or a false
absence claim; reviewer access does not retroactively give an extractor that evidence.

The index includes its algorithm revision in its digest. Changing heading/linking logic
invalidates its cache. A changed source/index during a mapped run requires a new run.
Neither the reference JSON nor its citations are used for indexing or retrieval.

## Budget behavior

Text is counted with `o200k_base` through tiktoken; if unavailable, UTF-8 byte length is
a conservative fallback. The tokenizer is an estimate for configured model aliases,
not a claim of the provider's exact billed token count. Initial encoding setup may
download tokenizer data; subsequent calls reuse its local cache.

Image cost uses dimensions and a non-upscaled tile proxy. Cropping reduces actual pixels
sent, but this estimate is **not provider image billing**. Trace records pixels, image
sizes, source/crop boxes and reported provider usage separately.

Heavy sections (1, 2, 3, 7, 9, 10, 14, 15, 16) get larger source budgets. Review gets a larger
text allowance, while reserving space for schema, instructions, target and both compact
answer drafts. A joint source budget counts selected text plus actual image proxy cost;
the final provider guard counts the complete serialized prompt, schema and images.
Extraction/blind keep at most four images for simple sections and six for heavy sections.
Review has a predefined allowance for their union: eight/twelve images respectively,
still within its image-proxy and complete-request token caps. This is not an expanded
source search or an outcome-triggered retry.

Optional bundles that do not fit are omitted atomically and recorded as coverage gaps.
Sources actually cited by either answer are mandatory for review. If mandatory evidence
does not fit, the stage fails before inference; it does not silently cut a table, retry
with expanded evidence or present missing source as verified absence. Inspect the metrics
and use an explicit new-run budget if the document genuinely requires more evidence.

The draft reservation is conservative. If only its joint total is exceeded, review checks
the complete serialized request, including policy, schema and output hint, before deciding.
A fitting request retains every mandatory source and records `reservation_warning`;
the unchanged final provider guard still enforces the complete request budget. Text, image
and image-count overflows cannot be bypassed this way.

Generation targets depend on section/role: extraction/blind 3,000–9,000 tokens and review
1,800–4,000 tokens. Codex treats these as prompt hints; the API adapter uses an API output
limit. Schema-complete responses are still required. A small token target does not prove
that every fact has been extracted.

## Measurement and quality gates

The full `run --benchmark-report` command writes end-to-end wall time. The sum of model
durations is also reported, but with parallel requests that sum exceeds wall time. Failed
calls/retries and recovery events remain in trace; cached/reasoning tokens are subsets
and must not be added again to their parent input/output totals. Missing usage is unknown.
Codex subscription inference has no fabricated API dollar cost.

The historical MAX3232 run `ce40e4a85acc4eb5` requested `gpt-6.1-sol / medium` with one
worker: 104m41s elapsed including interruptions/recovery, 86.12 minutes of successful
inference, 55 calls, 1,944,394 reported input tokens and 179,823 output tokens. It includes
four historical expanded calls. It is an observed baseline, not a controlled, uninterrupted
fresh run; do not turn its difference into a precise causal speedup claim.

Validation checks software behavior on synthetic fixtures and source availability on the
real PDF before live inference. Primary source checks cover pin mapping, existing circuit
and capacitor table, recommended conditions, electrical/timing rows and selected mechanical
drawing. A safe crop does not count as viewing an entire page in citation coverage.

Reference-citation coverage, requirement-status agreement and exact claim F1 are distinct
metrics. Broad page citations for absence decisions can lower citation coverage even when
the relevant table is available. Conversely, an available source does not prove the model
read it correctly. The MAX3232 reference remains an assistant-authored candidate pending
human review, so no overall extraction-accuracy percentage is certified by this benchmark.

## Current benchmark result

The optimized live benchmark is recorded separately from historical results. Until a
completed report is available, the 30-minute target remains unverified. Network/routing
timeouts, service throttling, large mandatory tables or additional variants can exceed it.

For a controlled comparison, run the same PDF/target/provider/model/reasoning with a new
run and `DATASHEET_OPTIMIZATION=baseline`, then another with `budget-v1`. Keep discovery
reuse, tokenizer cache and network conditions comparable. Compare exports with the
reference candidate and manually check source-grounded regressions, especially numeric
conditions and circuit connectivity.
